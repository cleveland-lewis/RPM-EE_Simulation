## Critical Issues (Effort: High)

### Issue #1: Non-Executable Python Modules
**Type**: Bug - Critical  
**Effort**: High (4-6 hours)  
**Category**: Architecture  
**Status**: Needs Approval

**Description**:  
All Python module files (`sensory.py`, `memory.py`, `emotion.py`, `rpm.py`, `simulation.py`, `replay.py`) contain code templates as string literals rather than executable Python code. The files define variables like `sensory_input_code = """\n...` instead of actual class definitions.

**Impact**:  
The simulation cannot run at all - throws `ImportError: cannot import name 'RPMEESimulation'`.

**Example**:
```python
# Current (WRONG):
simulation_code = """\
class RPMEESimulation:
    ...
"""

# Should be:
class RPMEESimulation:
    ...
```

**Fix Required**:  
Extract all string-embedded code and convert to proper Python module structure for all 6 files.

## High Priority Bugs (Effort: Medium)

### Issue #4: Sensory Input Missing Event Structure
**Type**: Bug  
**Effort**: Medium (2-3 hours)  
**Category**: Data Flow  
**Status**: Needs Approval

**Description**:  
`SensoryInputSystem.generate_input()` returns raw sensory data (vision, hearing, etc. as lists of dicts) but doesn't generate the event structure expected downstream. Events need:
- Unique ID
- Timestamp
- Timing (0.0-1.0)
- Single modality per event
- Emotion (added by tagger, but structure needed)
- Prioritization score (added by tagger)

**Current Output**:
```python
{
    "clock": 123,
    "state": "awake",
    "vision": [{"modality": "vision", "intensity": 0.8, "duration": 5}, ...],
    "hearing": [...]
}
```

**Expected Event Format** (from salience.py schema):
```python
{
    "id": "unique-id",
    "timestamp": "UTC time",
    "modality": "vision",
    "state": "awake",
    "novelty": 0.0-1.0,
    "emotion": {"valence": -1.0 to +1.0, "category": "awe"},
    "recurrence": 0,
    "timing": 0.0-1.0,
    "duration": 3,
    "intensity": 0.8,
    "prioritization_score": 0.0-10.0
}
```

**Fix Required**:  
- Either flatten sensory output to individual events, OR
- Implement proper conversion in `SalienceTagger.tag_input()`

### Issue #11: Clock Synchronization Issue
**Type**: Bug  
**Effort**: Low (30 mins)  
**Category**: Synchronization  
**Status**: Needs Approval

**Description**:  
`RPMEESimulation` has its own `self.clock` and `SensoryInputSystem` has its own `self.clock`. The simulation calls `self.sensory.update_clock()` which increments the sensory clock, then increments its own clock at the end of `run()`.

**Current**:
```python
def step(self):
    self.sensory.update_clock()  # increments sensory.clock
    # ...

def run(self, episodes=100):
    for episode in range(episodes):
        self.clock += 1  # increments simulation.clock
        self.step()
```

**Impact**:  
The two clocks get out of sync. After first episode: `simulation.clock=1`, `sensory.clock=1`. After second: `simulation.clock=2`, `sensory.clock=2`. This works but is redundant and confusing.

**Fix Required**:  
- Remove duplicate clock or synchronize them properly
- Pass clock as parameter to sensory.update_clock(clock)
- Or have sensory system reference simulation clock
